VT340 Phase 4 7FF2 firmware semantics
=====================================

Conclusion
----------

Shared byte 7FF2 is a result-state byte, not a CPU1-to-CPU2 request mailbox.
CPU1 writes 10 as a pending sentinel before it waits for CPU2 to publish a
checkpoint zero and, later, a final nonzero result. CPU2 never reads 7FF2.

Firmware cross-reference
------------------------

CPU1:

  3A08  MOV  DPTR,#7FF2
  3A0B  MOV  A,#10
  3A0D  MOVX @DPTR,A       install pending sentinel
  3A0E  LCALL 3AC9         send four-byte report
  3A11  LCALL 3B8E         DAT9 pulse/response exchange
  3A18  MOVX A,@DPTR       wait until CPU2 publishes zero
  3A31  MOVX A,@DPTR       then wait until CPU2 publishes nonzero
  3A3A  CJNE A,#80,3A4A    80 is success; other values are error results
  3AAF  MOVX A,@DPTR       error reporter maps the result to reports 08-0F

CPU2 writers:

  1369-136D  write 00      configuration checkpoint
  159A-159F  write $74     test error and stop
  1975-197A  write $74     computed test error and stop
  1B1D-1B24  write $74+B   computed test error and stop
  1639-163E  write 80      successful final result

There is no CPU2 read of 7FF2. Therefore 10 cannot notify CPU2 or request
work, and 00 cannot acknowledge consumption of that request. CPU2 is already
executing the test sequence under DAT9/startup control.

Observed failing lifecycle
--------------------------

  8.228779  CPU2 136D writes checkpoint 00
  8.295773  CPU1 3A0D writes pending sentinel 10, overwriting that zero
  8.295773-13.194725 CPU1 3A18 repeatedly reads 10
 13.194725  CPU2 163E writes final success 80
  after 13.194725 CPU1 3A18 repeatedly reads 80

CPU1 cannot reach its final-result loop at 3A31 until it observes zero at
3A18. The exact failure is thus: CPU2 publishes its sole checkpoint zero
before CPU1 installs the pending sentinel; CPU1 overwrites the checkpoint and
waits forever for a second zero that CPU2 never writes.

Effect on prior experiments
---------------------------

The report-delay and table-duration experiments remain valid. They establish
that native execution succeeds when the order is pending 10 -> checkpoint 00
-> final 80. They do not establish request/acknowledgement behavior, because
the firmware cross-reference rules out that interpretation.
